# CFile — overhaul audit (8.10.26)

Five readers went through all of `cfile.e` (0.5b51, 12210 lines) and the
project around it. Nothing was changed. Line numbers are against 0.5b51.

How each finding is known:
- **checked** — re-read in the source after the reader reported it.
- **read** — one reader's finding from the source, not yet re-checked.

None of this has been run on the Amiga yet. The fixes must be boot-tested.

---

## Plain summary

CFile builds cleanly, and the binary in the repo is exactly what the source
makes. The core (panes, copy, view) is in good shape. The trouble sits in
the edges that were added fast: archives, links, the tooltype editor,
and what happens when something fails half way (disk full, write
protected, Esc). Several of those failures can lose files. One bug
corrupts memory every time a folder is watched.

The code is one 12k-line file, with a second near-copy for Kickstart 1.3.
92 of its procedures differ from the main copy, and 185 are identical.
Both can be split into modules or merged with `#ifdef`; both ways were
tried with the compiler and work.

## 1. Can lose files — fix first

## 2. Can crash the Amiga

| # | Where | What happens | Known |
|---|---|---|---|

## 3. Hangs and leaks

- `livepipe` 9955 and `arcpollrun`: no way out if the child never closes its output or ignores Ctrl-C; Esc does nothing.
- Pipe opened after the async child starts (race), and a failed reader open leaves the child blocked.
- `sizedir` on a whole drive cannot be cancelled.
- `openfont` leaks a `textattr` per font change; `closeui` ignores a failed `CloseScreen` (a shell window left on CFile's public screen keeps it open).
- `arcviewsel` extracts members to `T:` with no size check and leaves `T:CFile-v/` subfolders.
- Notify messages not drained before `EndNotify`/`DeleteMsgPort`.

## 4. Wrong but harmless

- Folders over 500 entries are cut off without a word.
- Soft links to files show as folders, and a copy that meets one fails.
- `c` (ask) mode overwrites inside merged folders without asking.
- Archive extraction passes member names to lha/lzx as patterns (`a(1).txt`, `a*`); deletes already escape them.
- Names with `"` or `*` break every shell command (no escaping anywhere).
- Config with CRLF or tab separators is misread; a failed read rewrites it with defaults; lines over 298 chars are cut.
- DA unit numbers over 9; `daunmountall` may eject a disk the user mounted later on the same unit.
- Viewer: backward scrolling reads 4× more than needed; hex offsets wrap at 16 MB; ANSI art has no 80-column wrap or cursor moves.
- After a picture, the main window may not get the keyboard back (`ActivateWindow` missing).
- Non-UI exceptions exit with return code 0.

## 5. The shape of the code

**Repeated code that should be one helper each** (several bugs above live
in the copies that drifted):
- the skip/overwrite/rename collision prompt — 3 copies, already different
- the lha/lzx command batcher with its 600/700 magic sizes — 6 copies
- the "split buffer into lines" loop — 5 copies
- Up/Down/page/ends scrolling — 5 copies
- the console escape parser — 2 copies (`confeed`, `confeeddirect`)
- DIRECT and ONEXIT archive modes duplicate edit/new/move/delete.
  ONEXIT is the default. DIRECT holds most of the data-loss bugs.

**Missing helpers that would close whole bug classes:**
- `shellquote()` — escape `*` and `"` for every command
- a checked path join (`AddPart` failures are ignored everywhere)
- an archiver runner that returns the real exit code
- `safewrite()` — write to a temp name, then swap in
- unique scratch names from `FindTask(NIL)` (as `runname` already does)

**Giant procedures:** `infowindow` (330 lines), `viewfile` (330),
`arcxfer_out` (250), `editfile` (230), `eventloop` (a 40-branch IF chain).

**Dead code:** `opentry`, `prevline`, `textskip`, `ws` (compiler says
unreferenced); `capturecmd`'s refresh branch; BENCH mode (meant to go
before release).

**Magic numbers:** DiskObject offsets 22/26/50/54/66, viewer modes and
return codes, `dtcall` ops 0–4, the ±30000 jump markers, buffers of
204/300/314/700, sizes 1000/8000 written out instead of from `MAXENT`.

## 6. The project

- **Build:** `ecompile cfile.e cfile LARGE` (READMEs still say `evo`).
  Rebuilt today: both binaries byte-identical to the committed ones.
- **State:** idle since 1.8.26. b51 (`T` editor, 2.04 floor) is still
  "awaiting boot" — and D1 means it would have failed.
- **CFile13:** 185 procedures identical, 92 differ (the OS boundary),
  38 only in main, 24 only in 13. Fixes flow by hand in both directions.
  Every fix above that lives in shared code must be made twice today.
- **Docs:** about 145 KB of markdown. `todo.md` (45 KB) is mostly
  build history; of 27 boxes about 8 are open. `audit-roadmap.md` and
  `perf-audit.md` are fully closed. Many items say "pending" that are
  done (0.3.2, disk images, DMS, b48/b49, datatypes). README and
  `cfile.readme` stop at b47 and still say "2.0+"; CHANGELOG stops at b50.
- **Tests:** only the ISO parser harness (`tests/isoh.e`) and generators.
  Everything else is "boot it and look". wasabi + FS-UAE can now drive
  CFile remotely (keys, screen capture), so a real regression run is
  possible.
- **Licensing (public repo):** `cfile13/cfile13.adf` on GitHub carries
  Commodore's WB 1.3 C: commands, `icon.library`/`diskfont.library` and
  **`L:LZX.Keyfile`, a registration keyfile**.

## Proposed overhaul, in order

1. **Stop the bleeding.** One build per group, each boot-tested:
   C1 (notify size), D1 (tooltypes), D2 (links), D10 (blank line),
   D3/D4/D5 (archive failures checked, staging kept on failure),
   D9/D11 (safe write + Close check), C2 (cleanup on every exit).
2. **The helpers** from section 5 (shellquote, checked join, real exit
   codes, safewrite, unique scratch names). They retire most of the
   rest of sections 1–4 at once.
3. **One source for both CFiles.** `#ifdef KS13` first (cheap, ends
   cherry-picking), then modules (`ui`, `pane`, `fileops`, `archive`,
   `iso`, `viewer`, `editor`, `console`, `config`, `media`) with a small
   build script, since E-VO does not rebuild changed modules itself.
   Must happen before 0.6's key-table rewrite of `eventloop`.
4. **Drop the duplicates:** one collision prompt, one batcher, one
   scroller, one console parser; decide on DIRECT archive mode.
5. **A test run** in FS-UAE through wasabi: deploy, drive keys, compare
   screens, plus scripted file-op cases (links, full disk, protected
   archive, long names, `"` and `*` in names).
6. **Docs reset:** move the closed audits and build history to a
   `history/` folder, one short `todo.md`, README/readme/CHANGELOG
   brought up to b51.
7. Then release 0.5, and only then 0.6 features.
